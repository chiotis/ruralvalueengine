# Data contract (v0.1, draft)

## 1. Content read from ruralgreece.gr (WordPress REST, read-only)

Verified on 2026-11-27 against the public REST API. Content is read by the engine's sync job and cached; the app never calls WordPress directly.

| Engine entity | WP endpoint | Key fields used |
|---|---|---|
| `Business` (member listing) | `GET /wp-json/wp/v2/business` | `id`, `slug`, `title`, `link`, `featured_media`, taxonomies `location`, `business-type`, `price_range`, `kitchen_type`, `post_tag`; `acf`: `title_en`, subtitle and intro/main text (EL/EN), services, tourist packages, `address`, `email`, `telephone`, `website_url`, `booking_url` (external link only), `banner_image`, `photo_gallery`, `youtube_video`, `open_on`, `latitude`, `longitude` |
| `Route` | `GET /wp-json/wp/v2/route` | `id`, `title`, `categories`, taxonomies `activity`, `difficulty`, `location`, `path_markers`; `acf`: EL/EN text, length, duration, difficulty, `banner_image`, `photo_gallery`, `latitude`, `longitude`, `map_kml` (KML track URL) |
| `Poi` | `GET /wp-json/wp/v2/pois` | `id`, `title`, taxonomies `poi-type`, `activity`, `location`, `period`, `museum-type`, `museum-theme`, `monument-type`, `monument-status`, `ecosystem-type`, `beach-type`, `protection-status`, `path_markers`; `acf`: EL/EN text, `address`, contact fields, opening hours, `banner_image`, `latitude`, `longitude` |
| `Term` | `GET /wp-json/wp/v2/{taxonomy}` | `id`, `name`, `slug`, `parent` (for `location`: region → regional unit → place) |
| `Media` | `GET /wp-json/wp/v2/media/{id}` | `source_url`, `media_details.sizes` |

Notes:
- `latitude`/`longitude` are ACF **strings**; the sync job parses them to numbers and rejects out-of-range values.
- Sync is incremental using `modified_gmt` (`?modified_after=`), plus a nightly full pass to catch deletions.
- Webhooks: a small plugin (`rve-sync`) on each site will POST `{type, id, action: upsert|delete}` to the engine on save/trash so changes appear within seconds.

## 2. epaithros+

The members' platform (LMS, research, small services). Used for **member login** and membership status. Not yet inspected; to read: user/member records (id, name, email, role, membership status) and the field that links a member to its ruralgreece.gr `business`. Member login options: WordPress Application Passwords or a JWT/OAuth plugin on epaithros+, with the engine exchanging the result for its own session token.

## 3. Event envelope

All events, from any source, are normalised to:

```json
{
  "event_id": "01JDX8Y3T6M3S1N0Q8B7V2K4ZC",
  "type": "checkin.qr",
  "occurred_at": "2026-11-27T11:42:10Z",
  "received_at": "2026-11-27T11:42:12Z",
  "source": "app",
  "source_ref": "qr:biz-17789:v3",
  "visitor_id": "v_8f3c…",
  "member_ids": ["biz-17789"],
  "route_id": null,
  "poi_id": null,
  "package_id": null,
  "referral_id": null,
  "refers_to_event_id": null,
  "geo": { "lat": 37.5546, "lng": 22.0771, "accuracy_m": 18 },
  "verification": { "status": "verified", "checks": ["qr_signature", "time_window", "geo_distance"], "reason": null },
  "payload": {}
}
```

| Field | Rule |
|---|---|
| `event_id` | ULID, generated by the client (app or plugin). Same id re-sent → ignored (idempotent). |
| `type` | One of: `checkin.qr`, `checkin.geo`, `route.completed`, `referral.issued`, `referral.redeemed`, `partnership.created`, `wallet.redeemed`, `interaction.view`, `interaction.save`, `interaction.share`, `correction`, `cancellation` |
| `source` | `app`, `wp-ruralgreece`, `wp-epaithros`, `import`, `admin` |
| `visitor_id` | Pseudonymous engine id; never an email or phone number |
| `member_ids` | Engine member ids (`biz-<wp id>`); more than one for shared visits or packages |
| `refers_to_event_id` | Required for `correction`, `cancellation`, `referral.redeemed` |
| `verification.status` | `pending`, `verified`, `rejected` |

## 4. QR token

Each member or POI QR encodes `rve://c/<target>/<key_version>/<signature>`. The signature is an HMAC of the target and key version with a server secret, so codes can be rotated (bump `key_version`) without reprinting the others. The app sends the token; only the engine can verify it.

## 5. Rule output (ledger)

```
wallet_ledger(id, owner_type[visitor|member], owner_id, points, event_id, rule_version, reverses_id, created_at)
```

Balances are always `SUM(points)` over the ledger, never stored counters, so a recompute with a new rule version is possible and auditable.

## 6. Engine API (for the app), first cut

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/v1/catalog/{businesses,routes,pois,packages}` | Cached content, `?lang=el|en&location=&type=` |
| `POST` | `/v1/events` | Submit one or a batch of events (offline queue) |
| `GET` | `/v1/me/passport` | Verified experiences |
| `GET` | `/v1/me/wallet` | Balance + ledger |
| `POST` | `/v1/me/wallet/redeem` | Start a redemption |
| `GET` | `/v1/member/dashboard` | Score, visits, referrals |
| `POST` | `/v1/member/referrals` | Create a referral code |
| `GET` | `/v1/member/matches` | Matchmaking suggestions |
| `POST` | `/v1/member/partnerships` | Request or confirm a partnership |
